## 🧠 Understand it first

Lecture 9 is a toolbox of small features. A set keeps unique values; a constant gives a fixed value a clear name; a type hint documents what kind of value code expects; a docstring explains how a function should be used.

Comprehensions build collections compactly, `enumerate` pairs items with a counter, and a generator supplies values one at a time. `argparse` helps read named command-line options. These features make familiar ideas more expressive, but a normal loop is often the clearest choice. Type hints guide readers and tools; Python does not enforce them automatically.

### 🔍 Choose the right tool for the job

```python
numbers = [3, 2, 2, 5]

unique = sorted(set(numbers))
evens = [n for n in numbers if n % 2 == 0]
squares_total = sum(n * n for n in numbers)

print(unique)        # [2, 3, 5]
print(evens)         # [2, 2]
print(squares_total) # 42
```

1. `set(numbers)` removes duplicates. `sorted` makes the output order predictable because a set itself is not a sorted list.
2. The list comprehension says: “for each `n`, keep it if it is even.” It creates a list and keeps both 2s because both appeared in the original.
3. The generator expression inside `sum` produces one square at a time, so it can total the values without first building another list.
4. A type hint documents the kind of value a function expects or returns; it does not block a wrong value at runtime. `enumerate` adds a counter, and `argparse` turns command-line text into named options.

## 📝 Notes

### 1. Sets: keep only unique values

A **set** is a collection that does not keep duplicate values. Use it when you want to know which different items appeared:

```python
houses = ["Oak", "Pine", "Oak"]
unique_houses = set(houses)

for house in sorted(unique_houses):
    print(house)
```

Sets are useful for membership checks too: `if name in seen:`. Sets do not promise list-style ordering, so use `sorted(...)` when you want a predictable printed order.

### 2. Global variables and constants

A **global variable** is created outside a function. Functions can read it, but assigning to it from inside a function requires the `global` keyword. This can make it hard to see which part changed the value. Prefer a class for shared state, or pass the value into a function and return the updated value.

A **constant** is a value we intend not to change. Python does not enforce constants; uppercase names are a convention:

```python
MAX_TRIES = 5

def main():
    for _ in range(MAX_TRIES):
        print("Try!")
```

### 3. Type hints and mypy

A **type hint** documents what kind of value a function expects or returns:

```python
def square(number: int) -> int:
    return number * number
```

The `: int` hint describes the parameter. The `-> int` hint describes the return value. Hints do not automatically stop the program from receiving a different type at runtime. A separate tool such as **mypy** can inspect your code and flag likely type mistakes.

When a function only prints and returns nothing, use `-> None`:

```python
def cheer(times: int) -> None:
    for _ in range(times):
        print("You can do it!")
```

### 4. Docstrings explain how to use a function

A **docstring** is a description placed as the first statement inside a function, class, or module. It explains the purpose and, when useful, the input and result:

```python
def square(number: int) -> int:
    """Return number multiplied by itself."""
    return number * number
```

A regular comment often explains a line. A docstring explains a function’s public purpose so people and documentation tools can understand it.

### 5. Command-line options with argparse

A tiny script can inspect `sys.argv`, but that gets awkward when a program has options. The standard-library **argparse** module reads options, applies types/defaults, and creates a helpful `--help` message:

```python
import argparse

parser = argparse.ArgumentParser(description="Cheer a learner.")
parser.add_argument("name")
parser.add_argument("--times", type=int, default=1)
args = parser.parse_args()

for _ in range(args.times):
    print(f"You've got this, {args.name}!")
```

Run `python cheer.py Kritik --times 3`. The required `name` is a positional argument; `--times` is an optional named argument. `type=int` converts the option to an integer for you.

### 6. Unpacking, *args, and **kwargs

**Unpacking** takes items from a collection and assigns or passes them separately:

```python
first, second = ["Ada", "Grace"]

def add(a, b):
    return a + b

numbers = [2, 3]
print(add(*numbers))  # same as add(2, 3)
```

One star (`*`) unpacks a list/tuple into positional arguments. Two stars (`**`) unpacks a dictionary into named arguments.

In a function definition, `*args` collects any extra positional arguments into a tuple. `**kwargs` collects extra named arguments into a dictionary:

```python
def show_team(captain, *players, **details):
    print("Captain:", captain)
    print("Players:", players)
    print("Details:", details)
```

These are useful when building flexible functions, but ordinary named parameters are clearer when you already know what inputs you need.

### 7. Comprehensions, map, and filter

A **list comprehension** creates a list from another collection. Read it as “make this value for each item, keeping only items that pass this condition”:

```python
numbers = [1, 2, 3, 4, 5]
squares = [n * n for n in numbers]
even_squares = [n * n for n in numbers if n % 2 == 0]
```

A **dictionary comprehension** builds key/value pairs:

```python
squares = {n: n * n for n in range(1, 4)}
```

`map(function, items)` applies a function to each item. `filter(function, items)` keeps items for which the function is true. Comprehensions often make these simple transformations easier for beginners to read:

```python
names = ["ada", "grace"]
capitalized = [name.title() for name in names]
```

### 8. enumerate, generators, and iterators

`enumerate(items)` gives you both a count and an item:

```python
for number, name in enumerate(["Ada", "Grace"], start=1):
    print(number, name)
```

An **iterator** provides one item at a time. A **generator** is a simple way to create an iterator. Use `yield` to produce a value and pause until the next value is requested:

```python
def countdown(start: int):
    while start > 0:
        yield start
        start -= 1
```

A generator can save memory when there are many values, because it does not need to build the whole list at once.

## 🔬 Line by line: reading a comprehension

```python
words = ["apple", "fig", "banana"]
long_words = [word.upper() for word in words if len(word) > 3]
```

1. Python takes one `word` at a time from `words`.
2. It checks `len(word) > 3`.
3. If true, it makes `word.upper()`.
4. It collects the results into a new list.
5. The result is `["APPLE", "BANANA"]`. `fig` is skipped because it has only three letters.

Expanded into a normal loop, the same idea is:

```python
long_words = []
for word in words:
    if len(word) > 3:
        long_words.append(word.upper())
```

The loop version is longer but may be easier to understand at first. Both are valid.

## 📖 Key definitions

| Term | In simple words |
| --- | --- |
| Set | A collection that keeps unique values |
| Global variable | A name created outside functions and shared broadly |
| Constant | A value intended to stay the same, conventionally written in uppercase |
| Type hint | A note describing expected input or output types |
| Docstring | A description at the start of a function, class, or module |
| Unpacking | Taking values out of a collection into separate names or arguments |
| `*args` | Extra positional inputs collected into a tuple |
| `**kwargs` | Extra named inputs collected into a dictionary |
| Comprehension | A compact way to build a list, set, or dictionary |
| Generator | A function that produces values one at a time using `yield` |
| Iterator | An object that supplies values one at a time |

## ⚠️ Common mistakes

- Assuming type hints validate inputs while the program runs. They do not do that on their own.
- Using a complex comprehension that is harder to read than a regular loop.
- Expecting a set to keep items in the order you inserted them.
- Forgetting that `enumerate` normally starts at 0 unless you pass `start=1`.
- Using global variables when function parameters or an object would make the data flow clearer.
- Treating `yield` exactly like `return`: `return` finishes a function; `yield` pauses a generator so it can continue later.

## 🧑‍💻 Programming questions

### Q1. Remove duplicate names and print them alphabetically

**Task:** Given a list with repeated names, print each different name once in alphabetical order.

- **Try before opening.** What collection naturally removes duplicates? Why do we still sort?
    
    ```python
    names = ["Ada", "Grace", "Ada", "Kritik", "Grace"]
    for name in sorted(set(names)):
        print(name)
    ```
    
    **Why this works:** `set(names)` keeps only one copy of each name. A set is not for maintaining display order, so `sorted(...)` gives a predictable alphabetical order. The `for` loop then prints one name per line.
    

### Q2. Build a word-length dictionary

**Task:** Turn a list of words into a dictionary where each word points to its length. Add a type hint and a docstring.

- 
    
    ```python
    def word_lengths(words: list[str]) -> dict[str, int]:
        """Return a dictionary mapping each word to its length."""
        return {word: len(word) for word in words}
    
    print(word_lengths(["oak", "redstone"]))
    ```
    
    **Why this works:** The function receives a list of strings and returns a dictionary from strings to integers. The comprehension creates one key/value pair per word. The docstring explains what a caller can expect. The type hints document the shape of the input and output; they do not convert values or reject bad ones by themselves.
    

### Q3. Print names with their position

**Task:** Print the items in a list numbered from 1. Do not create a counter variable by hand.

- 
    
    ```python
    names = ["Ada", "Grace", "Kritik"]
    for number, name in enumerate(names, start=1):
        print(f"{number}. {name}")
    ```
    
    **Why this works:** `enumerate` gives a pair each time: the number and the current name. `start=1` makes the display friendly for people. The underlying list still uses indexes 0, 1, 2.
    

## 🎯 MCQs

- **Q1.** What happens to duplicates in a set?
A) They are all kept in order
B) Only one copy of each value remains
C) They are converted to dictionary keys
D) Python raises an error
    
    **Answer: B.** A set represents unique values.
    
- **Q2.** What does `-> None` say in a function type hint?
A) The function returns the text "None"
B) The function has no useful return value
C) The function accepts no arguments
D) The function is not allowed to print
    
    **Answer: B.** `None` is Python’s value for “no result”; a function that only prints commonly returns it.
    
- **Q3.** Which expression gives both a list position and its item?
A) `range(items)`
B) `zip(items)`
C) `enumerate(items)`
D) `sorted(items)`
    
    **Answer: C.** `enumerate` yields an index and a value together.
    
- **Q4. Tricky.** What does this print?
    
    ```python
    numbers = [1, 2, 3, 4]
    print([n for n in numbers if n % 2 == 0])
    ```
    
    A) `[1, 3]`
    B) `[2, 4]`
    C) `[4]`
    D) `True`
    
    **Answer: B.** The condition keeps values whose remainder after dividing by 2 is zero. The comprehension returns those original even numbers; it does not square them.
    
- **Q5. Tricky.** Does this type hint turn input into an integer?
    
    ```python
    def repeat(times: int) -> None:
        print("Hi" * times)
    ```
    
    A) Yes, hints convert values
    B) No, hints describe intent; they do not convert at runtime
    C) Only if `times` is a global
    D) Only when using `yield`
    
    **Answer: B.** If `times` came from `input()`, convert it explicitly with `int(...)`. A type checker may warn about a mismatch.
    

## ✅ Quick recap

- Sets keep unique values.
- Use globals sparingly; use uppercase names for values intended as constants.
- Type hints describe types; docstrings explain behavior.
- `argparse` handles command-line options and help.
- One `*` unpacks positional values; two `**` unpack named values.
- Comprehensions build collections; use a normal loop if it reads more clearly.
- `enumerate` supplies a counter; generators use `yield` to provide values gradually.
